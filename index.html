Logic Explanation

After the page loads (specifically for the event listeners), the Loot array is initialized as an empty array with nothing in it.

If the input in the Add Loot section is valid when the user adds loot with the Add Loot button, a new element with the data given (in the format {name: "x", value: y}) is made and pushed to the end of the array. Otherwise, an error is rendered.

After adding the loot, renderLoot() is run. If the user has previously split loot successfully, then the splitLoot() function is also run.

For rendering the array in the Loot List section, a for loop is used to simply go through the array while appending paragraph elements to the list container.

Paragraph elements added to said container are in the form of "Loot: x ($y)".

To get the total amount of the loot elements, a variable is used to keep track of how many times the previously mentioned for loop has run.

Splitting loot checks the party setup section and the Loot array.

If the input in the party setup section is less than 1 or not an number, or if there are no elements in the Loot array, then an error is rendered in the loot split section.

After the checks are made, the function uses an array (which is initialized at the start of the function) to distribute loot to the party, with equal value for each being prioritized.

Rendering the newly made array to the split loot section works mostly the same as rendering to the loot list, although another for loop is used to go through a party member's loot items so all of them are displayed properly.

Rendering the split loot works in this order: Member # > Loot (may take up multiple lines) > Member Total Value > hr > Member #...
